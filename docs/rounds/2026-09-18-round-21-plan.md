# Client round 21 — `/map`'s minimized address bar

*Wil's screenshot, 2026-09-18 13:45: scrolled into the index below the map
with the address bar minimized, "the gray gradient overlay … behind and around
the top address bar does not disappear when scrolling down the screen into the
section below the map. If it's not possible to remove the filter completely
then the color should change so that the color is the same color as the brown
… Gray is great on the map when it's visible but not on the section below it."
Base `c7baaef` (= the `v2` tip and the live site, Actions run 245), tagged
locally `client-round-21-base`. Revert: `git reset --hard client-round-21-base`.*

## Diagnosis

The grey is Safari's own tint on the minimized bar, and it comes from
`<body>`'s background colour (round 8 phase E, measured on his phone: Safari
reads `<body>`, not `<html>`, and ignores `theme-color`). `/map`'s body has
been the map's grey `#353535` since phase D/E so the at-rest bar matched the
canvas. Since round 17 the map itself paints behind the bar at rest (the T
runway), but the body colour still governs the minimized bar, and it never
changes as the index scrolls under it. The page cannot remove Safari's tint;
it can only hand it a colour. Phase A2 test C4a measured that a live colour
change on an element that stays in the tree moves the tint.

## What ships

- `Base.astro`, the edge sampler: on `/map` only (`data-root-fill="map"`),
  `<body>`'s background-color is written to the same colour the sampler
  already resolves for the `theme-color` meta — the map's grey while the map
  owns the screen, the ground's brown once the index does (the two-edge
  majority rule, sampled at most every 100 ms on scroll, one trailing sample).
  Nothing paints on the page: `<main>` covers `<body>` (round 14), so the
  colour reaches only the bar region and overscroll. Every other route is
  untouched.
- `global.css`: the note on the static `#353535` rule records that `/map`'s
  value is now the at-rest starting point the sampler moves from.

## Accepted cost

`<body>` has one colour, so the bottom toolbar's tint follows the same rule.
In the band where the map still fills more than half the screen and the index
has entered from below, the bottom pill reads grey over brown; once the index
owns the majority, both bars read brown. Safari animates the change (~300 ms).
