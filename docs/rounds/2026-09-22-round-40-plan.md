# Client round 40 — the bottom toolbar collapses on the way down, behind `?scroll=edge`

*Wil, 2026-09-22, after approving round 38 on the live links ("Works
great!"): "Is it possible to have the bottom toolbar disappear when the user
scrolls down? And then reappear when the user scrolls up while keeping the
area behind and around the bottom toolbar transparent and see-through when
it reappears … This should not affect the top tool bar in any way shape or
form." Told that it cannot be had as stated (§1), he reaffirmed: "The only
thing I want is the bottom bar to disappear when the user scrolls down. No
other changes." Base `3d9aa1c` (= the `v2` tip, round 38 live), tagged
locally `client-round-40-base`; the SHA is pinned in the manifest. Revert:
`git reset --hard client-round-40-base` — and off the flag nothing changed.*

## 1 · What the phone has already measured

- **Safari collapses its bars only when the document scrolls** (round 23,
  pass 8; playbook §3). The approved chapter pages are the still document:
  `<main>` scrolls, the document holds still, so the bars never move.
- **It collapses both bars together.** A page cannot hide the toolbar and
  leave the address bar; the playbook's geometry treats the pair as one
  transition. "Not affect the top bar in any way" is therefore not
  available to a page.
- **A static fill behind the top bar exists only where the document does
  not scroll.** Once it scrolls, the region behind the minimized bar shows
  whatever scrolled past, and every page-placed cover lags a frame (passes
  1–7, rejected on his phone each time).
- **The bottom toolbar is glass over in-flow page paint and nothing else.** A
  fixed or sticky box never paints under it (round 8, round 23 pass 5), and
  a fixed or sticky element found at an edge makes Safari paint that bar
  as an opaque fill (round 24, measured on `/paintings`; round 23 pass 16
  saw it hold over a transparent fixed `<main>`).

So the toolbar can collapse only in a plain scrolling document, the toolbar
is glass there by nature, and the top bar's solid colour can come from one
place only: Safari painting it opaque itself.

## 2 · What ships, behind the flag

**`?scroll=edge`.** On a chapter route the head script takes the flag ahead
of the iOS default: no `data-scroll="inner"`, so the chapter scrolls as a
plain document — the compositor moves the page, the bars collapse on the way
down and return on the way up, and the toolbar is glass over the chapter's
own text (nothing fixed and full-width touches the bottom edge; the mini
player and the corner menu are narrow boxes the probe skips). One element
is displayed: `.edge-trigger`, a fixed, invisible, hit-testable 8px strip on
the top edge, covered by nothing (the rail above it is `pointer-events:
none`, never the hit), so Safari's edge probe finds a fixed element there
and paints the top bar as an opaque fill in `<body>`'s colour — the section
at the top edge, which the sampler already writes and which switches at
each boundary. No cover, no visor, no runway, nothing placed by script.

**`?scroll=edge&band=<px>`.** The same, with the strip a visible band of
that height in the section's colour (`background-color: inherit` from
`<body>`, so the sampler's write reaches it with no script). The variant to
try if the invisible strip is not enough of a hit for the probe: it then
covers the other reading of round 24's rule, that the probe wants an opaque
fixed element.

**Off the flag: nothing.** The strip is `display: none`, the head script's
default branch still assigns `"inner"`, and every rule is keyed on the
attribute. The still document he approved is byte-identical.

**Why a flag, not the default.** CLAUDE.md rule 4: anything that depends
on browser chrome never ships to `v2` on assumption. Round 23's pass 17 was
this same idea shipped as the default, unread, and round 38 had to take it
back. The default flips only on his read, by one word in the head script.

## 4 · Device pass — what to look at, and what a FAIL looks like

| Where | Expected | FAIL looks like |
|---|---|---|
| `/bakery?scroll=edge`, scroll down | Both bars collapse; the page scrolls natively. | The bars stay expanded (the flag did not take). |
| Scroll up so the toolbar returns | The toolbar is glass over the chapter's own text — no fill. | A solid band under the toolbar. |
| The top bar, minimized, at any depth | Solid, the section's colour, switching at each boundary; no content through the pill. | The painting, a heading or the cream ghosting through the pill — then try `&band=12`. |

| Everything else | As round 38: the menu fading in place, the hero lockup one gutter above the toolbar, the mini player in its corner. | Anything moved. |
| Without the flag | Round 38 exactly. | Anything different. |
