# Client round 3 — Charles Nalle Walking Memorial (v2)

## Context

Wil reviewed the live site after round 2 (`7a80539`, deployed by Actions run 222) and filed eight edits plus a demand that the regressions introduced by the last round never recur. Everything since the v13 release (`de8d4ca`) lives in nine commits that touch only `src/`; no docs, scripts or workflow changed.

The exploration established the root causes, so the plan restores rather than guesses:

- **Round 2's full-bleed change is the mobile regression.** It introduced `--cnwm-bar = max(0, 100lvh − 100dvh)` and sized every full-bleed stage to `100lvh`. On Wil's iPhone (iOS 26, address bar on top) that token measures ~200px, not the ~90px the commit assumed. The card strip is `position: fixed; bottom: 0` and gained `+ --cnwm-bar` of padding, so the cards sit mid-screen (screenshot 4); the map shell is 852px tall in a 651px visible area, so the overview camera fits the five pins into a canvas whose bottom fifth is hidden (screenshot 3, pins 4 and 5 gone); the splash frame is `h-lvh`, so it overflows the viewport and the CTA floats 200px up (screenshot 2). The map camera constants, fit search and pitches are byte-identical to v13; nothing there needs "restoring" beyond the shell height and the two `+ bar` terms.
- **The dark bars are Safari's own chrome, tinted from the page's edges.** iOS Safari never draws page content around its address bar or toolbar; it extends a flat colour it reads at the page's top and bottom edges (the JetBlue effect is a solid blue header). Where the edge is a painting or the map it finds no flat colour and falls back to black. The site already carries the v12 mechanism for this (two 2px fixed strips + a scroll sampler in `src/layouts/Base.astro:113-216`), but the sampler deliberately leaves the strips transparent over artwork, which is exactly where Wil sees black. Round 2's `lvh` approach could not make the bars see-through and did not.
- **The films, the play glyph and the softer image are iOS Low Power Mode**, confirmed by Wil ("I turned off Low Power Mode and everything worked as normal"). The video loader (`Base.astro:329-377`) is byte-identical to v13: it swallows the rejected `play()` and leaves the `<video>` mounted above the still, so WebKit draws its play button over a frozen film. In that state the chapter hero shows the 480px poster tier, which is what reads as low resolution at DPR 3.

Decisions Wil made in this session (via questions):

| Topic | Decision |
|---|---|
| Low Power Mode | **Play on first tap**: until a tap, the crisp still with no play glyph; the first tap anywhere starts the films. |
| Bar colour over artwork | **Continue the artwork**: a build-time colour sampled from each hero painting's top edge; the map gets its own dark grey; reading sections cream; changes as you scroll. Plus a hidden test page so his phone shows exactly what Safari honours. |
| Splash CTA bottom padding | **56px phones / 64px tablets**. |
| Deploy | **Push `v2` after headless verification** (auto-deploys), report the run URL and the unverified list. |

Hard rules carried from the brief: only the listed items change; every animation keeps a reduced-motion variant; keyboard/focus intact; 375px works; URLs via `withBase()`; never touch `main`.

### Other · The regression guarantee (WP4 + CLAUDE.md)
No process can verify iOS chrome from this container, so the guarantee is three mechanical gates plus one rule, all zero-cost:
1. **Revert point**: every round starts with a tag (`client-round-N-base`); undoing a round is one command.
2. **Scope gate** `scripts/scope-check.mjs`: reads the round manifest (`docs/rounds/2026-09-16-round-3.json`, the allowed-file list from this plan) and fails if `git diff --name-only <tag>` contains anything else. Run before every commit and push.
3. **Visual gate** `scripts/snap.mjs`: Playwright captures 11 routes × 390/768/1440 at rest plus the map overview, museum rail, chapter hero and splash states (fonts settled, reduced-motion context, WebGL canvases masked) and compares against committed baselines in `docs/qa/baseline/` with a sharp-based pixel diff (no new dependencies, no lockfile churn); any drift outside the round's allowed pages fails and writes diff images. Baselines are captured from this round's final build and refreshed only for pages a round is allowed to change.
4. **Device-first rule** (written into `CLAUDE.md`): anything that depends on browser chrome or viewport units (`lvh/dvh/svh`, safe areas, tint) never ships to `v2` on assumption; it goes to the review branch/test page for Wil's phone first. Rounds 1–2 shipped `lvh` sizing on a simulated bar; this rule makes that impossible again.
Every round report ends with the checklist, the verified/unverified split and the revert command.
