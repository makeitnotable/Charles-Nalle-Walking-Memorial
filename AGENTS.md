# Charles Nalle Walking Memorial

Client memorial site for the Hart Cluett Museum (Troy, NY): a static Astro
site hosted free on GitHub Pages. Signed off by the client on 22–23 September
2026 and reduced to essentials for the handover on 23 September 2026 (the
build rounds, QA evidence and instruments live on in git history before that
date).

**Design work starts at `docs/v4/DESIGN-STANDARDS.md`** — the system contract,
with the source of every number. The acceptance bar is `docs/v4/CALIBER-RUBRIC.md`
(craft against three named reference sites, never fidelity to a spec).
Judgement calls and how to revert them: `docs/v4/DECISIONS.md`. Motion census:
`docs/v4/MOTION.md`. Naming is single-sourced from `name.{canonical,display,short}`
in the chapter JSON — the bronze plaques govern (`docs/v4/NAMING-CANON.md`).
`/styleguide` renders the whole system at real size.

Content corrections live in `docs/CONTENT-STATUS.md`; stack deviations from the
WBM constitution are in `docs/DEVIATIONS.md` (static Astro + GH Pages — no auth,
no billing, no database, no analytics accounts; zero ongoing cost is a hard
client requirement). The museum's operating manual is `docs/HANDOVER.md`; the
ownership transfer is `docs/HANDOFF-PLAN.md`.

Non-negotiables inherited from the constitution's design baseline:

- Every animation has a `prefers-reduced-motion` variant.
- Keyboard reaches everything; focus always visible.
- Works at 375px; tap targets ≥ 24px.
- Narrative text is Kathy Sheehan's domain — never rewrite story prose without a
  correction documented in `docs/CONTENT-STATUS.md`.
- Perf budget: Lighthouse mobile ≥ 90 perf / ≥ 95 a11y, LCP < 2.5s throttled.
- The base path differs per environment (GH Pages serves under
  `/Charles-Nalle-Walking-Memorial`; dev under `/`) — always build URLs with
  `withBase()` from `src/lib/url.ts`, never hardcode root-relative paths.
- **`main` is the only branch: the working branch and the deploy branch.** Every
  push to `main` auto-deploys to GitHub Pages via `.github/workflows/deploy.yml`
  (about three minutes; a newer push cancels an in-flight run). Never force-push
  `main`. The site is whatever `main` holds.
- A fresh clone has no `.env` (gitignored) and `astro dev` never reads
  `.env.production`, so `npm run dev` seeds one automatically (`predev` →
  `scripts/ensure-env.mjs`). Without it the map renders with an empty token.

**Mobile browser chrome — Safari 26's glass bars, full-bleed stages, viewport
units — is solved and the solutions transfer.** Read
`docs/PLAYBOOK-MOBILE-CHROME.md` before touching any full-bleed stage, the
bars' colour, or anything sized in `lvh`/`svh`/`dvh`. Anything that depends on
browser chrome never ships on assumption: it goes behind a flag (`?scroll=` on
the chapter pages) for a check on a real phone first — no instrument in a
container can see Safari's bars.

## Changing the site

- `npm run build` runs `astro build` and then `scripts/check-css.mjs` (six
  guards on the islands' CSS); a failed guard fails the deploy. `npm run check`
  type-checks.
- Before pushing: build, check, and look at every changed page at 390, 768 and
  1440 wide (Playwright's Chromium is a dev dependency; `npm run qa:setup`
  installs it).
- Media is regenerated by the `scripts/build-*.mjs` pipeline from `masters/`
  (see `masters/README.md`); never hand-edit a generated file.

## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.
